# Agent の固定ケース検証

`evaluation/questions.json` に手動で定義した 3 ケースを保存しています。CLI・Web API と同じ Agent フローで検索・回答・引用・根拠不足を確認し、既知の失敗を記録するための開発用の少数例です。Fujitsu RAG Hard Benchmark の全問題に対する評価や、独立したテスト集合の精度を示すものではありません。

## 実行と保存

```bash
uv run jp-doc-agent evaluate-rag

# ケースと保存先を明示
uv run jp-doc-agent evaluate-rag \
  --cases evaluation/questions.json \
  --output data/reports/agent-evaluation.json
```

モデル API の呼び出しが必要です。既定の出力先は時刻付きの `data/reports/rag-<時刻>.json` です。`--output` を指定した場合はそのファイルを上書きします。レポートには各ケースの期待値・判定・回答・引用・取得済み証拠の ID・ページ・設定・時間・Token 使用量・追加調査の履歴・停止理由を保存します。`data/` は Git の管理対象外です。

文書の指定と証拠ページは PDF の SHA-256 を使い、環境ごとの DB の連番に依存しません。実行前に全ての質問、必要な文書、証拠ページの範囲を検証します。文書が不足する場合は API を呼ばず、取り込みを案内します。

## ケースと判定

| ケース | 質問・範囲 | 期待する動作 |
| --- | --- | --- |
| `financial-revenue-scoped` | 2024年度第2四半期の売上収益。決算概要に限定 | 8,666 億円を回答し、許容する証拠ページを引用 |
| `organization-full-corpus` | 2021年1月1日時点の組織構成。全文書検索 | 組織資料の物理ページ 1 を取得・引用して回答 |
| `unsupported-year` | 2028年度第2四半期の売上収益。全文書検索 | 別年度の数値を流用せず根拠不足を示す |

期待するステータス・証拠ページ・キーワードは評価関数だけが使い、検索と回答生成には渡しません。文書に限定するケースは指定した範囲で評価します。

各ケースについて、次の項目を別々に記録します。

- `status_match`: 期待した回答可能・根拠不足と一致するか。
- `retrieval_evidence_hit`: 追加調査を含む取得済み証拠に、許容する証拠ページのいずれかがあるか。
- `citation_evidence_hit`: 実際の引用原文が、許容する証拠ページのいずれかと交差するか。
- `answer_keywords_match`: 定義した全キーワードが回答に含まれるか。全角・半角、数値の桁区切りカンマ、空白は正規化して照合する。

適用される項目が全て真なら `passed` です。根拠不足のケースで証拠ページを定義しない場合、証拠ページの項目は `null` にします。許容ページのいずれかの一致であり、複数ページの証拠の網羅率ではありません。キーワードの一致も、回答全体の意味や全ての条件・数値の正しさを保証しません。

`retrieval_evidence_hit_rate` は、証拠ページを定義し、正常に完了したケースのうち、証拠ページを取得できた割合です。API 失敗は分母から除外し、`errors` と各ケースの安全な理由に別途記録します。少数例から検索精度全体を推定しません。

API・引用検証のエラーでも他のケースを続けます。運用エラーがある場合は終了コード 1、評価が正常に完了した場合は品質上の失敗があっても 0 とし、`failed` とレポートで確認します。エラー結果は実行済み履歴と使用量も保存します。集計対象は実行結果を保存できたケースの検証済み応答で、再試行や応答形式の検証失敗を含む課金総額ではありません。

## 過去の開発記録

以下は問答を Agent に統一する前に、単回の基本 RAG と追加調査を比較した旧バージョンの結果です。単回 RAG の実装と比較モードは削除済みで、現在の CLI から選択する機能ではありません。導入時の効果とコストを示す開発記録として保持しています。

既定のモデル `gpt-4.1-mini-2025-04-14`、上位 5 件、同じ 5 文書・3 ケースで比較しました。基本 RAG は **2 成功・1 失敗**、Agent は **3 成功・0 失敗**、両方とも運用エラー 0 でした。

| ケース | 基本 RAG | Agent | 確認した内容 |
| --- | --- | --- | --- |
| 売上収益 | 成功 | 成功 | 初回検索で 8,666 億円を回答。物理ページ 31 の引用原文を照合 |
| 組織構成 | 失敗 | 成功 | Agent が一覧から組織資料を選び、文書に限定した追加検索で物理ページ 1・2 を取得・引用 |
| 未収録年度 | 成功 | 成功 | 2028 年度を別年度の数値で補わず根拠不足。Agent は文書一覧を確認して終了 |

| 合計指標（3 ケース） | 基本 RAG | Agent |
| --- | --- | --- |
| 証拠ページの取得 | 1 / 2 ケース | 2 / 2 ケース |
| 検索回数 | 3 | 4 |
| 道具呼び出し回数 | 3 | 6 |
| モデル呼び出し回数 | 3 | 8 |
| 所要時間 | 11.505 秒 | 21.414 秒 |
| 質問 Embedding Token | 89 | 112 |
| モデル入力 Token | 5,536 | 18,352 |
| モデル出力 Token | 176 | 1,250 |

組織構成では「初回検索 → 根拠不足 → 文書一覧 → 文書を限定した検索 → 回答」の順で追加調査しました。この比較では原文ページの道具を使わずに回答できました。ページ取得の原文・引用・上限は別途、一時 DB と模擬 API で検証しています。組織構成の成功判定は証拠ページ・ステータス・キーワードの一致です。組織図の全要素の網羅、役職と氏名の対応、全結論の意味を自動評価したものではありません。

Agent は既知の検索漏れを解消した一方で、モデル使用量と時間が増えました。モデルの出力や使用量は再実行で変わる場合があります。結果はローカルの `data/reports/rag-agent-comparison.json` に保存しています。先行する基本 RAG の実行記録 `data/reports/basic-rag-baseline.json` も保持しています。

根拠不足を返せたことと、回答できる問題を解けたことは別の結果です。過去の失敗も保持し、[Web API](web-api.md) の別実行で発生した引用不一致も記録しています。次の本格評価では、本文で回答可能な問題の選定、独立したテスト集合、意味・数値・条件の照合、人手での確認を追加します。
